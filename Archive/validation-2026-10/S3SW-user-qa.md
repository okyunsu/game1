# PROC-001 사용자 QA 요약 1쪽

## 무엇이 바뀌었나
AGENTS에 기존 회귀 재사용·새 검증 도구 금지·사람 판단 항목 직접 QA·실패 원인 구분 규칙을 추가했다. 기존 규칙은 지우지 않았고 운영 절의 충돌 우선순위를 명시했다. PROCESS_METRICS에 S2-night 이후 실행과 N5~N8 1회 회고를 근거와 함께 정리했다. 이번 실행의 새 플레이 기능은0개, 게임·빌드 내용은 그대로다.

## 어디서 해 보나
이번에는 게임 실행이 아니라 `AGENTS.md`의 운영 규칙, `PROCESS_METRICS.md`의 실행 표·집계 정의, `TASKS.md`의 PROC-001 결정/Latest Handoff 한 줄을 읽어 확인한다. Unity 실행은 하지 않았다. 기존 N9 인계와 검증 상태는 수정하지 않았다.

## 의심 지점 3개
1. 이후 작업에서 새 검사 도구가 다시 생기거나, 조작감·가독성·난이도를 자동 PASS로 수락하는지 확인한다. 예외는 사용자 승인된 Release Candidate 검수뿐이다.
2. 회귀 FAIL을 바로 게임 변경 탓으로 보아 복원하는지 확인한다. 원인 불명 RouteAll FAIL 빌드는 사용자 플레이용으로 안내하기 전에 **플레이 전 확인 필요** 표시가 있어야 한다.
3. 활동 구간을 실작업 시간으로 읽거나, KNOWN-LIMIT을 BLOCKED에 섞거나, 하나의 Task·후보 묶음을 중복 계수하는지 확인한다. 특히 N8 판정 철회와 N9 103.1분/기능3개를 점검한다.

구현 세부 판단: 지표는 승인 Task의 독립 플레이 결과 단위로 묶고, 부모 Task에 포함된 빌드·종속 산출물을 중복 계수하지 않았다. 시각이 없는 부분은 기록 없음으로 남겼다. 앞으로 최소2~3회 실행 후 운영 개선을 판단한다.
