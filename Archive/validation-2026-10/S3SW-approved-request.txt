## 1. AGENTS.md — "운영 규칙 (3단계, PROC-001)" 절 추가
기존 규칙은 지우지 않는다. 아래 내용을 새 절로 추가하고, 기존 규칙과 충돌하면 이 절이 우선한다고 적는다.
- 변경 확인은 기존 회귀 묶음(`Validation/Run-Regression.ps1`, RouteAll·PogoTest 포함)을 우선 사용한다.
- 새 검증 도구는 만들지 않는다. 예외는 Release Candidate 검수 단계에서 사용자가 승인한 경우뿐이다.
- 조작감·가독성·난이도·화면 표시처럼 사람이 판단할 항목은 자동 검사하지 않고 사용자 직접 QA로 넘긴다.
- 기존 회귀 실패가 이번 변경 때문이라고 재현되면 그 변경을 우선 수정하거나 복원한다.
- 검사 도구 오류·환경 한계·원인 불명 결과는 게임 변경의 실패로 보지 않는다. REVIEW 또는 BLOCKED로 기록하고 새 검증 도구를 추가하지 않는다. 단, 원인 불명이면서 RouteAll이 실패한 상태라면 그 빌드를 사용자 플레이용으로 안내하지 않고 "플레이 전 확인 필요"로 표시한다.
- 실행 중 사용자 답변을 기다리지 않는다. 막히면 Decisions Needed에 기록하고 다음 항목으로 넘어간다.
- 명세에 구현 세부(처리 순서 등)가 없으면 Codex가 판단하고, 그 판단을 인계에 한 줄로 남긴다.
- 실행 끝마다 PROCESS_METRICS.md에 한 줄을 추가하고, 인계에 "사용자 QA 요약 1쪽"(무엇이 바뀌었나 / 어디서 해 보나 / 의심 지점 3개)을 포함한다.

## 2. PROCESS_METRICS.md 작성 (저장소 루트)
### 정의 (문서 맨 위에 고정)
- **실측 시간:** progress 파일 등에 시작·종료 시각이 명시된 경우만. 사용자 대기·중단 시간은 빼지 않고 그대로 두되 비고에 적는다.
- **커밋 활동 구간:** 실측 기록이 없을 때 첫 커밋~마지막 커밋 시각 차이. 실제 작업 시간이 아니며, 생각·대기·중단이 섞일 수 있다고 명시한다. 실측과 같은 열에 쓰되 "활동"으로 표시한다.
- **플레이 가능 기능:** 사용자가 exe 또는 Editor에서 직접 해 볼 수 있는 새 기능이나 완성된 기능. 내부 검사 도구·문서·리팩터링·검증 결과는 세지 않는다.
- **BLOCKED/복원:** 그 실행에서 BLOCKED 처리되거나 되돌려진 Task 수.
- **발견 주체:** 버그·문제를 처음 찾은 쪽. 셋 중 하나: 기존 자동 회귀 / 직접 플레이 QA / 구현 중 Codex 자체 발견.

### 표
| Run | 작업 범위 | 시간(실측/활동) | 플레이 가능 기능 | BLOCKED/복원 | 발견 주체 | 비고 |
- 과거 실행을 git 로그와 Validation 기록으로 채운다. 대상: 확인 가능한 범위의 모든 실행(최소 S2-night 이후, F1, S3-complete, F2/LOG, D0/F2R/LOGR, TM/U1, Q-night4, N5, N7, N8, N9).
- 비고에는 BLOCKED 원인을 짧은 태그로 붙인다: `[규칙]` 명세·허용 범위 때문, `[도구]` 검사 도구 문제, `[게임]` 실제 게임 결함, `[대기]` 사용자 판단 대기.
- 기억이나 추정으로 채우지 않는다. 근거가 없으면 칸을 "기록 없음"으로 둔다.
- N8 행: 당시 "자동 완주 17구간 PASS"는 N9 감사(`N9-N8-route-csv-audit.txt`)에서 철회됐다(R05 A04 사망 후 CP-A03 복귀를 목표 도달로 잘못 인정). 플레이 가능 기능에는 위 공격만 세고, 비고에 `[도구] 완주 판정 철회`를 적는다.
- N9 행: 실측 103.1분. 플레이 가능 기능은 아래 공격·포고, PogoTest, 난이도 후보 빌드(H1~H3)를 각각 센다. RouteAll FAIL은 비고에 `[도구] 입력 라이브러리 R05 사망`으로 적는다.

### 2단계 회고 (표 아래, 한 번만)
- N5~N8 구간에서: BLOCKED 원인 태그별 건수, 자동 검증이 찾은 실제 게임 결함 수와 목록, 검사 도구 수정 관련 커밋 수(커밋 메시지 기준, 대략치라고 명시).
- 이 회고 계산은 이번 한 번만 한다. 앞으로 매 실행 지표에는 넣지 않는다.

### 3단계 성공 기준 (표 아래에 고정)
"같거나 더 많은 플레이 가능 기능을 내면서, `[도구]`·`[규칙]` 원인의 BLOCKED가 줄고, 사람이 판단할 문제가 직접 QA에서 발견되는 것." 기능 수가 크게 늘지 않아도 BLOCKED 감소만으로 개선으로 본다. 최소 2~3번 실행한 뒤 판단한다.
