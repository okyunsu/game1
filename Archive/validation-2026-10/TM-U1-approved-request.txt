## U1 — 누락·부분 항목만 구현 (PRD에 있는 것만)
U0에서 "없음/부분"인 항목만 구현한다. PRD 밖 UI(맵, 설정, 키 재지정 등)는 추가하지 않는다.
1. `UITuning` ScriptableObject(Header·단위·Tooltip): HUD 위치·크기, HP 칸 크기·간격, 안내 표시 시간, 사망 표시 시간, 글자 크기. 값은 Inspector에서 조정 가능하게 둔다.
2. HUD(화면 왼쪽 위, 하나로 통합):
   - HP: "HP n/5" 텍스트를 칸(5칸, 남은 칸 흰색 / 잃은 칸 회색)으로 바꾼다. HP 값은 PlayerHealth.HP를 읽기만 한다.
   - 능력: 대시·더블 점프 아이콘 2개(획득 전 회색 윤곽, 획득 후 흰색 + 키 표기). 보유 상태는 읽기만 한다.
   - 방 ID 표시는 유지한다(지역 표식 겸 플레이테스트 기록용). 기존 "Attack X (J)…" 줄은 HUD로 옮기면서 K1 키 표기로 정리한다.
3. 첫 조작 안내: 새 게임 첫 A01 진입 시에만 "←→ 이동 / Z 점프 / X 공격 / Esc 일시정지" (패드 사용 중이면 패드 표기). UITuning의 시간만큼 보이거나 첫 이동 입력 후 사라진다. 저장 형식은 바꾸지 않는다(이어하기에서는 표시하지 않아도 됨).
4. 더블 점프 획득 안내: 없으면 대시와 같은 형식으로 추가한다.
5. 사망·리스폰 표시: 없으면 GameState.Respawning 동안 화면을 어둡게(반투명 검정) 하고 리스폰 후 걷어낸다. 사망 0.6초 흐름·입력 차단 시간은 바꾸지 않는다.
6. 저장 실패 안내·Pause·엔딩·타이틀이 U0에서 "있음"이면 손대지 않는다.
- 합격(`Validation/U1-ui.txt`): 상태 기준으로 HUD HP 칸 수 = HP, 능력 아이콘 상태 = 보유 플래그, 첫 안내는 새 게임 A01에서만 표시·이어하기에서는 미표시, 획득 안내 표시 시간, 사망 중 오버레이 활성 → 리스폰 후 비활성. 1280×720·1920×1080 스크린샷 각 3장(A01 시작, 피격 후, 두 능력 획득 후)을 `Validation/U1-shots/`에 저장한다(판단은 사용자가 한다). 회귀 묶음 전 항목이 TM 결과와 같거나 더 좋음. Error 0.
- 상태: REVIEW(가독성·위치는 사용자 판단).
