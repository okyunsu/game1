이번 실행은 아래 순서로 수행한다: 1부(저장 버그 수정, 체인) → 2부(검증 도구 제작과 실행, 큐). 2부의 각 항목은 서로 독립이다. 하나가 실패해도 기록하고 다음으로 넘어간다. 모든 항목을 끝내기 전에는 종료하지 않는다. 튜닝 기본값 변경, 레벨 배치 변경, 새 게임 기능 추가는 하지 않는다. push 금지.

## 지난 실행에서 바뀐 점 (먼저 읽기)
지난 큐는 40분 만에 끝났다. 원인은 작업 수가 아니었다. Q2~Q5는 "필요한 검증 도구가 없고 코드 수정 금지"라는 이유로 바로 BLOCKED 처리됐다. **이번 실행의 본 작업은 그 도구를 만드는 것이다.**
- **도구가 없다는 것은 BLOCKED 사유가 아니다.** 도구가 없으면 만든다. BLOCKED는 도구를 만들어 실행했는데 같은 원인으로 2회 실패했을 때만 쓴다.
- 검증 도구는 아래 "검증 도구 규칙"을 지키면 런타임 스크립트로 만들어도 된다.
- 화면을 봐야 하는 검사(해상도, 스크린샷, 포커스)는 **숨김 창·-batchmode·-nographics로 실행하지 않는다.** 지난번 검정 스크린샷과 "창을 찾을 수 없음"은 숨김 실행 때문일 가능성이 높다. 먼저 일반 창으로 실행해 본다.

## 1부 — BUG: 손상·미지원 저장에서 타이틀 메뉴가 멈춤 (체인, 수정 허용)
Claude 원인 확인:
- `ProgressSave.TryLoad`는 빈 파일(`FromJson("")`→null), 버전 불일치, 알 수 없는 체크포인트에서 `InvalidDataException`을 던진다. 그런데 catch 필터는 `IOException / UnauthorizedAccessException / ArgumentException`만 잡는다. `InvalidDataException`은 `IOException`의 하위 클래스가 아니어서 예외가 밖으로 나간다.
- 그 결과 `SaveMenu.Start`가 중간에 끊겨 UI 입력 연결이 안 된다. 메뉴가 키 입력에 반응하지 않을 가능성이 있다(Q1-corrupt-empty/version 증거).

할 것:
1. catch 필터에 `InvalidDataException`을 추가한다. JsonUtility가 잘못된 JSON에서 던지는 예외도 포함해, 손상 저장 관련 예외를 모두 "읽을 수 없음" 메시지 경로로 보낸다. 다른 줄은 바꾸지 않는다.
2. 검증: Q1의 손상 4종(잘림·빈 파일·잘못된 JSON·미지원 버전) 모두 실제 exe에서 확인한다. Menu 시작 → Continue 비활성 → 메시지 표시 → **키보드로 새 게임 선택 → 손상 파일이 `.invalid-*`로 보존되고 새 게임 시작**. Error/Exception 0.
3. 회귀 묶음 13/13, S2-04 기존 저장 검사 PASS → S2-04 BLOCKED를 REVIEW로 되돌린다.
4. 실패 처리: 1회 수정 후 재실패 시 복원하고 BUG를 열어 둔다. 1부의 결과와 상관없이 2부는 진행한다.

### T-C. 입력 녹화·재생 도구 (Q4 경로 시간의 기반)
- `InputRecorder`(`-record <파일>`): 플레이 중 Gameplay 입력(이동 축, 점프/공격/대시 누름·뗌)을 FixedUpdate 시각 기준으로 저장하고, 시작 씬·스폰·능력 상태도 같이 저장한다.
- `InputReplayer`(`-replay <파일>`): 같은 시작 상태에서 가상 장치로 재생하고, 구간별(방 입장 시각) 시간과 최종 위치를 기록한다.
- 검증: Codex가 짧은 지정 입력 시퀀스(A01 시작 → 오른쪽 이동·점프 → A02 입장)를 녹화하고 60fps에서 3회 재생해 방 입장 시각과 최종 위치 차이를 측정한다(합격: 입장 시각 ±1 물리 틱, 위치 ±0.05u). 이어서 30/120fps에서도 재생한다.
- 사용자가 나중에 자기 플레이를 `-record`로 녹화하면 그 파일로 Q4 구간 시간을 잴 수 있도록, README에 녹화·재생 명령 3줄을 추가한다.
- 결과: `Validation/N5-TC-record-replay.txt`
