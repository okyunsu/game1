# 04 — 보스1 공유 계약 (방 세션 ↔ 보스 세션)

두 세션이 같은 숫자를 쓰기 위한 고정 값이다. **어느 한쪽도 혼자 바꾸지 않는다.** 바꿔야 하면 작업을 멈추고 사용자에게 올린다.
좌표는 A04 방 로컬 좌표(Unity unit, 왼쪽 아래 0,0). A04 크기 50×12는 유지(world 배치 불변).

## C-1. 아레나

| 항목 | 값 |
|---|---|
| 아레나 범위 | x **24 ~ 49**, y **1 ~ 11** (안쪽 폭 25, 높이 10) |
| 바닥 | y=1 평지, x24~49 연속. 구덩이·hazard·발판 없음 |
| 천장 | y=11 (기존). 아레나 안에 발판·고체 추가 금지 |
| 오른쪽 벽 | x49 기존 벽. ClimbableWall 아님(보스1은 벽 점프 시험 아님) |
| 왼쪽 잠금벽 | x **23 ~ 24**, y1~11, id `V5-A04-bossgate`. 평소 열림(없음), 전투 중 닫힘 |
| 바닥 구멍 | 기존 문 `A04-A05` x44~49 y0. 처치 전에는 **봉인(seal) 덮개** `V5-A04-bossfloor`로 막힘 |

참고: B3 아레나는 x1~19(폭 18). 보스1은 폭 25로 넓게 잡아 회피 공간을 준다. 몸 크기(D-BODY)가 바뀌어도 이 폭은 유지한다.

## C-2. 트리거

| 항목 | 값 |
|---|---|
| 시작 조건 | 플레이어 발이 x ≥ **27** 그리고 y ≤ 4 (아레나 바닥에 내려섬). 위 통로를 지나기만 해서는 시작하지 않는다 |
| 시작 시 | 잠금벽 닫힘 → 0.8초 등장 연출(경고 표시) → 첫 패턴 |
| 보스 첫 위치 | x **42**, 바닥 위. 플레이어 쪽을 봄 |
| 진입 경로 | 아레나로 내려오는 길은 방 세션이 만든다. 단 x24~27 사이 바닥에 착지할 수 있어야 한다(트리거 전 안전 착지) |

## C-3. 보상 연결 [추천·미확정: D-BOSS1-LINK]

- 처치 → 잠금벽 열림 + 바닥 덮개 `V5-A04-bossfloor` 제거 → 구멍으로 A05 낙하 가능
- 대시는 A05 사당에서 얻는다(현행 유지). 보스가 직접 능력을 주지 않는다.
- 저장: `boss1Defeated`(보스 ID `B1-A04`). 처치 즉시 저장. 재진입 시 보스 없음, 덮개 없음, 잠금벽 없음.

## C-4. 사망·재시도

- 전투 중 사망 → 체크포인트 **CP-A03**(A03 허브, 신규)로 복귀. 보스 HP·패턴 초기화.
- 다시 아레나 바닥에 내려서면 C-2대로 재시작.
- 처치와 사망이 같은 프레임이면 처치 우선(기존 B3 규칙).

## C-5. 보스1 전투 사양(보스 세션이 구현, 초안 수치)

| 항목 | 값 |
|---|---|
| 바탕 | 기존 `BossEncounter` + 새 Asset `Assets/BossCandidates/B1/BossTuning.asset` |
| HP / 접촉·공격 피해 | 14 / 1 |
| 페이즈 | 1 (2페이즈 끔) |
| 켜는 패턴 | **도약**(착지점 벗어나기) · **충격파**(점프) · **돌진**(점프로 넘기, 속도 B3보다 느리게 7~8u/s 후보) |
| 끄는 패턴 | 근접(대시 회피 전제), 추적 연타, 백스텝 탄, 연속 도약, 낙하물 |
| 포고 | 보스 윗면에 아래 공격이 맞으면 튕김(PogoTarget). 회피 겸 공격 수단 — "포고를 배운 플레이어의 시험" |
| 능력 전제 | 대시·벽 점프·더블 점프 **없이** 이길 수 있어야 함 |
| 목표 | 첫 승리 2~5분, 숙련 1분 안팎 |

## C-6. 데이터 필드(방 세션이 넣고 보스 세션·생성기가 읽음)

`rooms_v5_A.json`의 A04에 추가:
```json
"boss": {"id": "B1-A04", "arena": [24, 1, 25, 10], "gate_wall": [23, 1, 1, 10],
         "trigger": {"x_min": 27, "y_max": 4}, "spawn": [42, 1],
         "floor_cover": {"id": "V5-A04-bossfloor", "rect": [44, 0, 5, 1]},
         "checkpoint": "CP-A03"}
```
hazard 복귀 필드(12-1): `"hazard": [[x, y, w, h]]`와 같은 순서로 `"hazard_return": [[x, y], ...]`.
